# HANS AIML Report

## 1. Dataset Used

For the current AIML phase, we are using a synthetic dataset generated by the custom Gymnasium environment for HANS navigation.

- The dataset is not collected from real robot runs.
- Each episode generates state transitions from the simulated 2D environment.
- The dataset consists of sequences of:
  - distance to goal
  - angle to goal
  - simplified LiDAR obstacle buckets
  - action commands (linear and angular velocity)
  - reward signals

This synthetic dataset is appropriate for early-stage model prototyping and debugging before ROS/Gazebo integration.

## 2. Preprocessing

The preprocessing pipeline is intentionally lightweight to preserve real-time compatibility.

- Distance is computed as Euclidean distance between robot and goal.
- Angle is normalized to the range `[-pi, +pi]`.
- LiDAR readings are reduced from a full scan to `10` sector buckets.
- All observations are concatenated into a fixed-size vector of shape `(12,)`.
- Action outputs are clipped to the robot-safe ranges:
  - linear velocity: `[0.0, 0.22]`
  - angular velocity: `[-2.84, 2.84]`
- No additional normalization is required inside the Gym environment because the feature ranges are already bounded.

## 3. ML Model / DL Model / AI Model

The current AIML architecture uses:

- `stable-baselines3` PPO (`Proximal Policy Optimization`)
- Policy type: `MlpPolicy`
- Environment: custom `HANSNavEnv`
- Observation space: continuous vector
- Action space: continuous control over linear and angular velocity

This is a reinforcement learning model rather than a supervised deep learning model. PPO is chosen because it is stable and well-suited for continuous control problems like navigation.

## 4. Train / Test / Validation / Training Split

In reinforcement learning, the dataset is generated on the fly, so the split is handled by episode design:

- Training: main PPO learning loop with `total_timesteps=100000` (default)
- Validation / evaluation: separate evaluation episodes after training
- We use deterministic policy rollout during evaluation to measure performance without exploration noise

Planned workflow:

1. Train the agent on the simulated environment for a fixed number of timesteps.
2. Save checkpoints periodically during training.
3. Evaluate the saved model on a set of hold-out episodes.
4. Compare performance between training and evaluation runs.

## 5. Corrections and Comparisons

For this initial AIML phase, the main comparison strategy is:

- Baseline random policy vs trained PPO policy
- Untrained policy performance vs learned policy performance
- Episode reward and episode length as primary comparison metrics

Correction strategy includes:

- Adjusting reward shaping if the agent learns bad behaviors
- Adding stronger progress reward when the robot moves closer to the goal
- Penalizing collisions heavily to discourage unsafe navigation
- Increasing environment difficulty only after a stable baseline is achieved
